# Conventions

- `CANON:1` [MODEL 2026-09-01] Les skills du marketplace sont rédigés en français, ton directif, structure calquée sur roadmap-tracker (Où vit / Grammaire / Opérations courantes / Garde-fous) ; le README du repo reste en anglais.
- `CANON:2` [MODEL 2026-09-01] Les descriptions de frontmatter des skills doivent déclencher sur les situations concrètes (« avant de coder », « à la clôture »), sans exiger le mot-clé du skill.
- `CANON:3` [MODEL 2026-09-01] La grammaire des fichiers canon appartient au skill canon-tracker ; les autres skills la consomment et n'en redéfinissent jamais une variante.
- `CANON:8` [USER:eddy 2026-09-24] Les agents et skills distribués restent génériques : aucune mention d'un projet ou d'un outil particulier (Unity, prefab, Éditeur…) ; les spécificités d'un projet vivent dans le canon de ce projet, que l'orchestrateur lit via sa gate de lecture.
- `CANON:9` [USER:eddy 2026-09-24] Toute modification d'un skill ou d'un agent distribué incrémente la version du plugin (`plugins/*/.claude-plugin/plugin.json`, semver) et ajoute une entrée dans `CHANGELOG.md` ; la version de `.claude-plugin/marketplace.json` suit à chaque changement du catalogue.
- `CANON:11` [MODEL 2026-09-24] L'effort de raisonnement d'un agent délégué ne se passe pas à l'appel de l'Agent tool (seul `model` se passe à l'appel) : il se fixe par le champ `effort` du frontmatter d'un agent défini (`low|medium|high|xhigh|max`), ou par `opts.effort` d'un `agent()` dans un script Workflow. Les agents livrés par un plugin ignorent `hooks`, `mcpServers` et `permissionMode` (doc code.claude.com/docs/en/sub-agents).
- `CANON:16` [MODEL 2026-09-28] Le plugin `level-design` applique `CANON:8` : aucun moteur ni pack d'assets nommé ; ses chiffres sont des valeurs de départ mesurées sur le projet de jeu, que le canon du projet utilisateur remplace ; les pièges propres au moteur restent dans le canon du projet.
- `CANON:17` [USER:eddy 2026-09-29] Le skill `level-design-build` ne commite jamais : le working tree revient à l'humain, comme pour `roadmap-tracker` et l'orchestrateur.

- `CANON:21` [USER:eddy 2026-09-29] Le plugin `level-design` (skills, références, agent) ne fixe aucune distance absolue : hauteurs, largeurs, espacements, portées et densités s'expriment en modules et cellules du kit, en multiples du gabarit joueur mesuré, en secondes de course ou en proportions, et se complètent à partir des assets 3D de l'utilisateur du skill.
- `CANON:22` [USER:eddy 2026-09-30] Répartition des modèles du plugin `roadmap` : le `scribe` est le point d'entrée (reformulation, questions, canon, roadmap) sur un modèle économe ; l'`orchestrateur` (workflow, délégation, réception) sur le modèle le plus capable autorisé ; les `executant-*` sur un modèle plus petit, corrigés par un advisor (`/advisor`) réglé au niveau de l'orchestrateur quand l'utilisateur l'a configuré. La gamme la plus coûteuse est interdite (refusée par `scripts/validate.py`). Un modèle ne se nomme qu'à un seul endroit : la ligne `model:` du frontmatter de l'agent ; jamais dans le texte des agents, skills et manifestes distribués (`plugin.model-mention`), ni dans `README.md` ou `CLAUDE.md` — seuls le validateur et sa spec (`docs/grammar.md`) citent les gammes pour les vérifier.
- `CANON:24` [USER:eddy 2026-10-02] L'API des Mods est en early access : aucun nom d'événement ou de surface n'est inventé, seules les déclarations générées par `/plugin-types` (versionnées dans `.claude/types/`) font foi ; tout changement de config est montré à l'utilisateur avant d'être appliqué, et une phase du plan ne démarre qu'après validation de la précédente.
- `CANON:25` [MODEL 2026-10-02] La variable `CLAUDE_CODE_EFFORT_LEVEL` écrase l'effort de session (`--effort`) et le champ `effort` du frontmatter de chaque agent (constaté en 2.1.287 par la sonde du Mod `session-recap`) : tant qu'elle est posée, le choix d'effort de l'orchestrateur (`CANON:11`) est sans effet. Un sous-agent en `inherit` prend le modèle de son parent immédiat.
- `CANON:27` [USER:eddy 2026-10-05] Le `scribe` n'est plus le point d'entrée (une session Claude Desktop ne peut pas démarrer avec lui). L'agent principal (« default »), le `scribe` et l'`orchestrateur` sont trois pairs égaux qui se parlent directement (`SendMessage`, messages courts par IDs et chemins) ; le scribe tient canon et roadmap mais ne relaie ni ne recopie rien, pour ne pas saturer son contexte. Remplace le rôle de point d'entrée de `CANON:22` ; la répartition des modèles reste.
