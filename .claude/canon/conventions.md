# Conventions

- `CANON:1` [MODEL 2026-09-01] The frontmatter descriptions of skills must trigger on concrete situations ("before coding", "at task close"), without requiring the skill's keyword.
- `CANON:2` [MODEL 2026-09-01] The grammar of canon files belongs to the canon-tracker skill; the other skills consume it and never redefine a variant of it.
- `CANON:4` [USER:pazimor 2026-09-24] Distributed agents and skills stay generic: no mention of a particular project or tool (Unity, prefab, Editor…); a project's specifics live in that project's canon, which the orchestrator reads through its read gate.
- `CANON:5` [USER:pazimor 2026-09-24] Any change to a distributed skill or agent increments the plugin version (`plugins/*/.claude-plugin/plugin.json`, semver) and adds an entry to `CHANGELOG.md`; the version of `.claude-plugin/marketplace.json` follows every change to the catalog.
- `CANON:6` [MODEL 2026-09-24] The reasoning effort of a delegated agent is not passed when the Agent tool is called (only `model` is): it is set by the `effort` field of the frontmatter of an agent definition (`low|medium|high|xhigh|max`), or by `opts.effort` of an `agent()` call in a Workflow script. Agents shipped by a plugin ignore `hooks`, `mcpServers` and `permissionMode` (doc code.claude.com/docs/en/sub-agents).
- `CANON:10` [MODEL 2026-09-28] The `level-design` plugin applies `CANON:4`: no engine or asset pack is named; its figures are starting values measured on the game project, which the user's project canon replaces; engine-specific pitfalls stay in the project canon.
- `CANON:11` [USER:pazimor 2026-09-29] The `level-design-build` skill never commits: the working tree is handed back to the human, as for the orchestrator.
- `CANON:12` [USER:pazimor 2026-09-29] The `level-design` plugin (skills, references, agent) sets no absolute distance: heights, widths, spacings, ranges and densities are expressed in modules and cells of the kit, in multiples of the measured player gauge, in seconds of running, or in proportions, and are completed from the 3D assets of the skill's user.

- `CANON:56` [USER:pazimor 2026-10-08] The Mod API is in early access: no event or surface name is invented; only the declarations generated by `/plugin-types` (in `.claude/types/`, regenerated locally on each Claude Code version and not tracked by git) are authoritative; every config change is shown to the user before being applied, and a phase of the plan starts only once the previous phase is validated.
- `CANON:17` [USER:pazimor 2026-10-05] The `scribe` is no longer the entry point (a Claude Desktop session cannot start with it). The main agent ("default"), the `scribe` and the `orchestrator` are three equal peers that talk to each other directly (`SendMessage`, short messages citing IDs and paths); the scribe keeps the canon but neither relays nor copies anything, so as not to saturate its context.
- `CANON:19` [USER:pazimor 2026-10-08] The orchestrator starts from the most economical model as soon as a task has an independent executable criterion for the executor; it raises the model on a comprehension failure and the effort on an application failure, and goes straight to the most capable model when a failure would not show up in the criterion (review, judge, architecture, audit, framing, broad exploration); it treats model and effort as two independent axes, follows the routing table of the project canon when one exists, and reports, per task, the model and effort of each attempt.
- `CANON:20` [USER:pazimor 2026-10-08] The success criterion of a delegated task never rests on the tests written by the executor alone: existing tests or acceptance cases written in the brief, plus held-out cases that the orchestrator runs itself on return.
- `CANON:21` [USER:pazimor 2026-10-08] Each agent launch pays a fixed prefix: the orchestrator groups the mechanical micro-tasks of one scope into a single brief; executors, orchestrator and scribe remove the built-in tools they do not need via `disallowedTools`; the orchestrator sets `effort: high` instead of inheriting the session's effort.
- `CANON:22` [USER:pazimor 2026-10-08] The `scribe` runs on the most economical model, set in its frontmatter, and is called without `model`; it is the only agent of the `orchestration` plugin that sets its own model. The `orchestrator` is called without `model` and inherits the session's model; it chooses and passes the model of each executor at the call (`CANON:19`), among those the user's settings allow, where the exclusion of the most expensive tier lives. A model is named only on a `model:` line of agent frontmatter (`plugin.model-mention`).
- `CANON:24` [MODEL 2026-10-08] In the desktop app in 2.1.293, each subagent launch writes ~60k tokens of prefix (system instructions, tools) on the first call, before the brief; simultaneous launches of the same model do not share this prefix, whereas successive launches less than 5 min apart reread ~37k from the cache.
- `CANON:25` [MODEL 2026-10-08] The alias of the most economical model depends on the Claude Code version: in 2.1.293 it resolves to the 5.5 generation (effort setting available), in 2.1.287 to the previous generation, with no effort setting.
- `CANON:26` [MODEL 2026-10-08] Since 2.1.293, the Agent tool accepts an `effort` at the call (`low…max`), which its description reserves for explicit requests from the user, a `CLAUDE.md` or a skill; `CANON:6` remains true for earlier versions and for effort chosen per `executor-*`.
- `CANON:27` [MODEL 2026-10-08] Scribe benchmark of 2026-10-08: the most economical model at `effort: xhigh` succeeds at a typical pass as well as the mid-tier model does, at 3 to 5 times less cost; a scribe pass climbs to 130–230k prompt tokens, beyond the 100k threshold where the most economical model bills ~5 times more per token (it remains cheaper than the mid-tier model); so there is no auto-compaction window at 100k for it (`modelSettings`, 2.1.288+), which would compact it in the middle of a pass.
- `CANON:29` [USER:pazimor 2026-10-08] In an agent's file, the design to use for its mascot in the `agents-info` band is specified by adding data where the model and effort go; by default, the base mascot is used. The inspector is not used for now: it serves testing and debugging.
- `CANON:30` [MODEL 2026-10-08] Clarifies `CANON:29`: the data is the `mascot:` field of the agent's frontmatter; the catalog of roles is `scribe` (scribe), `chef` (orchestrator), `artist` (`level-design-reviewer`) and `inspector` (reserved for testing and debugging).
- `CANON:31` [MODEL 2026-10-08] Clarifies `CANON:29`: the catalog of tiers has one mascot per model tier, from the most economical to the most capable (`courier`, `artisan`, `scholar`, `mage`), and `bare` as the fallback.
- `CANON:32` [MODEL 2026-10-08] Clarifies `CANON:29`: Claude Code ignores the `mascot:` field, which is unknown to its agent frontmatter.
- `CANON:33` [MODEL 2026-10-08] Clarifies `CANON:29`: `scripts/validate.py` emits the WARN `frontmatter.mascot` when the value of `mascot:` is not in the catalog (`CANON:30`, `CANON:31`).
- `CANON:34` [MODEL 2026-10-08] Clarifies `CANON:29`: the `agents-info` Mod finds a plugin agent's definition via `~/.claude/plugins/installed_plugins.json`, an internal, undocumented and therefore fragile file (`CANON:56`); if no definition is found, it falls back to the mascot of the model's tier.
- `CANON:40` [USER:pazimor 2026-10-08] Everything in the repo is written in English — skills, agents, docs, canon, CHANGELOG, code comments and UI strings — so the repo can be promoted to an English-speaking audience; skills and agents keep a directive tone and a shared structure (Where it lives / Grammar / Common operations / Guardrails).
- `CANON:41` [USER:pazimor 2026-10-08] The canon grammar keywords are English, with no backward compatibility for French files: `— obsolete YYYY-MM-DD: <reason>`, `(promoted from MODEL)`; the expectations theme is `expectations.md` and the forbidden catch-all is `misc.md`. A project with French canon files migrates them by hand.
- `CANON:42` [USER:pazimor 2026-10-08] Distributed identifiers are English: agents `orchestration:orchestrator` and `orchestration:executor-{low,medium,high,xhigh,max}`; mascots `scribe`, `chef`, `artist`, `inspector`, `courier`, `artisan`, `scholar`, `mage`, `bare`; level-design references `pitfalls.md`, `recipes.md`, `exterior.md`, `interior.md`, `rendering.md`; level-design dials `OPENNESS`, `DENSITY`, `RELIEF`, `NATURE`.
- `CANON:44` [USER:pazimor 2026-10-08] The Mod formerly named `session-recap` is named `agents-info`: folder `plugins/agents-info/`, install `agents-info@marketplace`, command `/agents-info`, tools `mcp__agents-info__plan` / `mcp__agents-info__step`.
- `CANON:54` [MODEL 2026-10-08] The Mods engine (2.1.287) refuses a pane render where a `Box` that carries both a `key` and `display: "none"` is the scope of `hover: { display: "flex" }`, since the pointer can never be over it: the hover card must be an unkeyed `Box` inside a visible keyed `Box`.
- `CANON:55` [USER:pazimor 2026-10-08] One-time exception to the rule that a canon ID is never renumbered: on 2026-10-08 the canon was renumbered to close the gaps left by the entries that went away with the legacy and the English translation, keeping their order (old → new table in `CHANGELOG.md`, marketplace 0.13.0). Outside this operation, an ID is never renumbered or reused.
